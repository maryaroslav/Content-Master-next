# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Content Master is a social/community app (posts, communities, events, follows, private chat) being migrated from two separate projects into a pnpm + Turborepo monorepo on branch `migration/monorepo`. The step-by-step plan lives in `docs/MIGRATION_PLAN.md`, which is intentionally untracked and must not be committed (only that file is excluded; `docs/adr/` is tracked). `Content Master SRS.docx` / `SDD.docx` are the requirements and design documents in Czech, rewritten for the current architecture in phase 8d; architecture decisions are recorded in `docs/adr/` (add a record for a new significant decision), and `README.md` / `CONTRIBUTING.md` are the entry points for people.

- `apps/api` (`@cm/api`): Express 5 + Sequelize (MySQL 8) + Socket.IO, port 5001
- `apps/*/Dockerfile` + `docker-compose.yml` (ADR 0010): pruned multi-stage builds from the repository root; the API image is `pnpm deploy --prod` output and migrates on start (`GET /health` for the health check), the web image is the standalone Next server (`NEXT_OUTPUT=standalone`, set only in the Dockerfile because `next start` does not support it); root `.env.example` holds the compose variables
- `apps/web` (`@cm/web`): Next.js 16 App Router + React Compiler (`reactCompiler: true`) + `@cm/auth` + TanStack Query + next-intl, port 3000
- `packages/contracts` (`@cm/contracts`): zod schemas and inferred types for API requests/responses, compiled to `dist/`. The root export is the camelCase API v1, including the endpoint catalog (`endpoints.ts`, one `defineEndpoint` per route) from which the build also writes `dist/openapi.json`, and the Socket.IO event catalog (`realtime.ts`: `clientEvents` with payload and ack schemas, `serverEvents`, the derived `ClientToServerEvents` / `ServerToClientEvents` and `Ack<T>` = `{ ok: true, data } | { ok: false, error }`).
- `packages/api-client` (`@cm/api-client`): TanStack Query hooks + models generated by orval from `@cm/contracts/dist/openapi.json` into `src/generated/` (gitignored; the `generate` turbo task runs before build/typecheck/lint/dev and on `pnpm install` via the root `postinstall`). `src/http/` holds the axios instance: the app calls `configureHttp({ getBaseUrl, getAccessToken, refreshAccessToken, onAuthFailure })`; a 401 triggers one shared refresh and a single retry. ESM package (`"type": "module"`, Bundler resolution) so the web app and the hooks share one `@tanstack/react-query` instance; `getErrorMessage(error)` reads the API error message. `@cm/api-client/mocks` exports the MSW handlers orval generates for every endpoint (`get<Operation>MockHandler(override?)`, MSW 2: orval imports from the `msw` root, which MSW 3 removed); only tests import it.
- `packages/auth` (`@cm/auth`): client session on top of the v1 auth endpoints of `@cm/api-client`. Access token in memory only (`getAccessToken()`), session restored on startup from the refresh cookie (`AuthProvider`), `useAuth()` → `{ status: 'loading' | 'authenticated' | 'unauthenticated', user }`; `login` / `loginWithTwoFactor` / `register` / `logout` (never rejects: the local session ends and other tabs are told even when the request fails; a failed request leaves `cm-auth-logout-pending` in `localStorage`, and until a logout gets through every refresh resends it instead of using the cookie, so a reload cannot restore the session; a login clears it) / `refreshAccessToken` / `updateUser`. Refreshes are deduplicated in the tab and serialized across tabs with a Web Lock (a reused rotated refresh token revokes the whole session); login/logout are broadcast to other tabs. `getFreshAccessToken()` refreshes when less than 30 s of the token remain, for callers without the axios retry (raw `fetch`, Socket.IO handshake). ESM, like `@cm/api-client`.
- `packages/realtime` (`@cm/realtime`): Socket.IO client over the `@cm/contracts` event catalog. `createRealtimeClient({ url, getToken })` (lazy socket, token on every handshake, reconnects when the server ends the connection at token expiry, one retry after a rejected handshake); `emit(name, payload)` resolves with the `Ack` (or `NOT_CONNECTED` / `TIMEOUT`); `on(name, handler)` delivers only payloads that pass the event schema. React: `RealtimeProvider({ client, enabled })`, `useRealtime()`, `useRealtimeConnected()`, `useRealtimeEvent(name, handler)`. No knowledge of the chat or of query keys. ESM, like `@cm/auth`.
- `packages/forms` (`@cm/forms`): `useZodForm(schema, options)` — react-hook-form 8 (beta: v7 breaks under the React Compiler, e.g. `reset()` does not clear inputs; `@hookform/resolvers` still declares v7, allowed in `pnpm-workspace.yaml`) with `zodResolver`, typed from the schema's input and output; `applyServerErrors(setError, error, fields)` puts the API's validation `details` on the matching fields and anything else on `root.server`; re-exports `FormProvider` / `useFormContext`. ESM, like `@cm/auth`.
- `packages/ui` (`@cm/ui`, ADR 0020): the design system in code on Material UI 9 + Emotion. `src/tokens/tokens.json` (same shape as the "Content Master" Design System artifact on claude.ai) → `src/theme/` builds the MUI theme at runtime (`cssVariables`, schemes on `[data-theme="light|dark"]`; `primary` = the blue accent, `ink` = the main-action button colour (`color="ink"`), every other token in `palette.cm` / `theme.vars.palette.cm.*`; `spacing` 4px; `theme.radius`, `theme.size`; typography variants incl. `display`, `bodyLg`, `label`, `code`; elevations from the per-scheme shadow tokens). Module augmentation in `src/theme/augment.ts`. A test fails on a WCAG contrast miss in either scheme (`src/tokens/contrast.ts`). `UiProvider` = `ThemeProvider` (light until phase 10c ends) + `CssBaseline`. Own composite components use `styled()`/`sx`. `src/theme/components.ts` restyles the MUI components to the design system (no ripple, focus ring from `cm.focus`; `Button` defaults to `variant="contained" color="ink"`, plus `variant="soft"` (grey), `outlined`, `text`, `color="primary"` (blue) / `"error"`; inputs 40px (32 small, 48 large), outlined, no notch; soft-tinted `Chip` and `Alert` per colour; `Card` outlined; `List`, `Menu`, `Dialog`, `Tabs`, `Badge` (dot in `accentBright`), `Tooltip`, `Link`). Screens use only `@cm/ui` (a construction kit; ADR 0020): its own API with design-system props — `Typography` (`variant` display/h1/h2/h3/bodyLg/body/bodyStrong/small/label/caption/overline/code, `color` default/muted/accent/danger/success, `align`, `truncate`, `as`), `Stack` and `Form` (`direction`, `gap` on the 4px scale, `align`, `justify`, `wrap`, `grow`), `Card` (`padding`), `Tag`, `Button` (`variant` primary/accent/secondary/outline/ghost/danger, `size`, `startIcon`/`endIcon` by name), `IconButton` (`icon`, `label`, `tone`, `dot`), `Icon` (named Rounded icons, `src/kit/icons.tsx`), `TextLink`, `ActionMenu`, `Alert` (`action`), `LoadingState`, `ErrorState`, `EntityList`/`EntityRow` (image or `leading`, `overline`, `title`, `meta` lines, `action`, `href`/`onClick`, `selected`, `unread`), `ConfirmDialog`, `WizardDialog` (`progress`, `title`, `description`, `error`, `back`/`next`; reset the steps in `onExited`), `ChoiceCard`, `RadioList`, `ImagePicker`, `TabsBar`; plus the wrappers `TextField` (label above the field, `hint`, `error` message, `showCount` + `maxLength`, `code` for 6-digit codes, `ref` goes to the `<input>` for `register()`), `SelectField`, `SearchField` (`onSearch`), `Logo` / `LogoMark`; composites and layouts with no data or i18n inside (texts come in as `labels` props, dates as formatted `time` + `dateTime`): `UserAvatar` (initials on an illustration colour, `unread` dot, `decorative`), `SectionCard`, `EmptyState`, `DaySeparator`, `MessageBubble` (`status` sent/pending/failed, Retry/Discard), `Composer` (`onSend` with trimmed text, clears at once; `onAttach`), `PostCard` (`author.username` optional: shown as @username only when it differs from `name`), `PostComposer` (`onSubmit` returns whether to clear: `true` clears, `false` keeps the draft; `error` under the text; a pick over `maxImages` is refused with `labels.tooManyImages`; Ctrl/Cmd+Enter submits), `UserMenu`, `Header`, `NavTabs` (links with `aria-current`, not ARIA tabs), `AppShell` (name the side columns with `startLabel`/`endLabel`), `AuthLayout`, `ChatLayout`, `SettingsLayout`. `UiProvider linkComponent` makes every MUI `href` render that component; the web app passes `next/link` from `Providers.tsx` (a component cannot cross from the server layout), and `test/render.tsx` wraps tests in the same `UiProvider`. Icons come from `@mui/icons-material`, Rounded variants only (the old SVGs in `apps/web/src/images/icons` are replaced as screens move). Put list rows in `ListItem disablePadding` around `ListItemButton` (a bare button in `<ul>` fails a11y). Text on `lilac`/`amber`/`butter` (avatar initials) uses `cm.onIllustration`. Built with Vite library mode (`'use client'` banner, React Compiler applied; MUI/Emotion are peers, `emptyOutDir: false` so the declarations survive) to `dist/index.js`; types from `tsc`; `dev` runs `vite build --watch` and `tsc --watch` in parallel. Storybook 10 (`pnpm --filter @cm/ui storybook`, port 6006, addon-a11y fails on violations, scheme toolbar); `pnpm --filter @cm/ui test` runs the unit tests and every story as a test in headless Chromium (`@storybook/addon-vitest`, `vitest.config.ts` projects `unit` and `storybook`; play functions for the counter, select, search, menu, dialog, composer, message retry and post submit behaviour; every `@mui/*` import under `src/` is pre-bundled in `vitest.config.ts`, since a dependency discovered mid-run reloads the page and fails the stories rendering at that moment), so the package's tests need the Playwright Chromium (`pnpm --filter @cm/ui exec playwright install chromium`; CI installs it in the verify job). ESM.
- `packages/env` (`@cm/env`): zod-validated environment for the web app. `publicEnv()` (`API_URL`, `APP_ENV`, `REALTIME_URL` — the Socket.IO origin, connected to directly because the Next proxy does not carry WebSockets; everything in it is sent to the browser) reads `window.__ENV__` in the browser and `process.env` on the server; `serverEnv()` (`API_ORIGIN`) is server-only.
- `packages/config-ts`, `packages/config-eslint`: shared tsconfig presets (`base`, `node`, `library`, `nextjs`) and ESLint configs

## Commands

Node 24 (`.nvmrc`), pnpm version pinned in `package.json` (`corepack enable`). `.npmrc` sets `save-exact` and `engine-strict`; syncpack enforces exact versions and `workspace:*` for internal packages.

```sh
pnpm install
pnpm dev                 # all apps except @cm/e2e (it would build web first); api runs pending migrations first, then tsx watch
pnpm build | typecheck | lint | circular | test   # via turbo, all packages
pnpm test:integration    # api tests against a throwaway MySQL database
pnpm test:e2e            # Playwright against built apps on ports 3100/5101 and a throwaway database
pnpm knip                # unused files/exports/deps
pnpm syncpack:check      # dependency version rules

pnpm --filter @cm/api <script>                     # one package
pnpm turbo run typecheck lint --filter="...[HEAD]" # only changed packages + dependents

pnpm --filter @cm/api db:migrate | db:rollback | db:status
```

`@cm/api-client`, `@cm/auth`, `@cm/forms` and `@cm/realtime` have unit tests (`test/`, vitest; `@cm/realtime` runs a real socket.io server). `apps/web` (`apps/web/test/`, vitest + jsdom + Testing Library) compiles components with the React Compiler like the app; the network is MSW (`test/server.ts`, unhandled requests fail the test, handlers from `@cm/api-client/mocks` with fixed data from `test/fixtures.ts`), the session is the real `@cm/auth` (`signIn()` logs in through a mocked endpoint, `test/setup.ts` logs out after each test), `renderWithProviders` / `renderHookWithProviders` (`test/render.tsx`) add Query, next-intl (real messages, `locale`, `now`) and a test realtime client (`createTestRealtime()`: `emit` is a mock, `deliver` fires server events); `next/navigation`, `next/image` and `next/link` are mocked in `test/next.tsx`. `apps/api` (vitest, `apps/api/vitest.config.mts`) has two projects:
- `pnpm test` → `test/unit/`: no database, env values fixed in `test/setup/unit.ts`.
- `pnpm test:integration` → `test/integration/`: `test/setup/integrationGlobal.ts` creates `cm_test_<random>` on the MySQL server from `apps/api/.env`, runs the migrations with `tsx src/db/cli.ts up`, and drops it afterwards; files run one at a time and call `resetDatabase()` before each test. Helpers (`api()`, `createUser()`, `totpFor()`, `testImage()`, ...) are in `test/integration/helpers.ts`. v1 responses are asserted with the `@cm/contracts` schemas. Rate limits are off when `NODE_ENV=test`.

`e2e/` (`@cm/e2e`, Playwright, Chromium) tests the whole system: `playwright.config.ts` starts the built API (`cm_e2e_<random>` database created by `support/prepare-database.ts`, migrated, temp upload dir, `NODE_ENV=test`) and `next start` on their own ports, so a running `pnpm dev` is untouched; `support/global-teardown.ts` drops the database. Tests create their own users through the API (`support/api.ts`: `createUser`, `follow`) and sign in through the UI (`support/ui.ts`), so they run in parallel; the 2FA test reads the manual key that Settings shows next to the QR code. `turbo run test:e2e` builds the apps first (`@cm/api` and `@cm/web` are devDependencies of `@cm/e2e` only for that); install the browser once with `pnpm --filter @cm/e2e exec playwright install chromium`.

The husky pre-commit hook runs `typecheck lint circular test` (unit tests only, no MySQL needed) for affected packages plus `syncpack lint`; CI additionally runs `build`, `knip` and `test:integration` against a `mysql:8.4` service, a parallel `e2e` job runs `test:e2e` (report uploaded on failure), and a `docker` job builds both images, starts `docker-compose.yml` and runs the Playwright suite against the containers (`E2E_EXTERNAL=1` skips Playwright's own servers and database; the API container runs with `NODE_ENV=test` only to lift the auth rate limits). There is no local Docker; Docker images can only be built in CI, but each Dockerfile step can be reproduced locally (`turbo prune @cm/<app> --docker`, `pnpm --filter @cm/api --prod --config.inject-workspace-packages=true deploy <dir>`, `NEXT_OUTPUT=standalone` build of the web app).

Every turbo task `dependsOn: ["^build"]`, so `@cm/contracts` must be built before consumers typecheck — turbo handles this, but running `tsc` directly in `apps/api` after changing contracts requires `pnpm --filter @cm/contracts build` first.

## Web architecture (`apps/web/src`)

`Providers.tsx` calls `configureHttp` and wraps the app in `QueryClientProvider` → `AuthProvider` → `RealtimeProvider` (one socket for the app, connected while the session is authenticated); there is no other client state store. The session lives only in the browser (access token in memory, refresh cookie), so server components cannot see it and access is checked on the client by route group: `(protected)/layout.tsx` (`RequireAuth`: waits for the session, guests go to `/login`) holds `(main)`, `chat`, `profile/[username]`, `settings`; `(guest)/layout.tsx` (`GuestOnly`: signed-in users go to `/explore`, which is also how a finished login leaves the form) holds `login` and `register`; the welcome page `/` is outside both. The forms (`(guest)/components/LoginForm`, `RegisterForm`, `TwoFactorStep`) validate with the request schemas of `@cm/contracts` before calling `@cm/auth`; they are on `@cm/ui` (`AuthPage` wraps `AuthLayout` with the illustration, `TextField` shows each field's error under the field, an `Alert` the form error). `typedRoutes` is on: links to pages that do not exist fail typecheck. `MainSidebar`, the communities screen (`community/components/`, on `@cm/ui`: owned and joined `SectionCard` lists, optimistic leave on the `useUsersMyCommunities` cache shared with `MainSidebar`; the create wizard is a MUI `Dialog` whose form lives inside it, so closing resets it, it checks each step's fields with `trigger` before moving on, and invalidates both lists), the chat (`chat/components/`: conversations and an infinite message history from the v1 hooks; chat state shared with the rest of the app lives in `src/chat/`: `ChatRealtime` (rendered by `(protected)/layout.tsx`) merges `message:new` into the history and conversation caches on every page and marks the peer unread unless it is the open chat; unread peers, the open peer and unsent messages are tab-local entries of the query cache (`useLocalQuery`), so logout clears them; `useChatSender` sends text optimistically (pending bubble with `clientId`, replaced by the ack, `failed` with Retry/discard) and images after the upload; the header shows a dot while there are unread peers; an image is uploaded first (`POST /chat/attachments` creates an unsent row in `attachments`) and then sent by `attachmentIds`; `chatService.sendMessage` accepts only the sender's own unsent attachments; a failed send shows the error code under the input), search (the page reads `q` from `searchParams`; communities carry `isMember` and have Join/Leave), the explore feed the events list, the profile (`profile/[username]/components/`: follow with an optimistic update of the profile query; the own profile links to Settings) and Settings (`settings/components/`: profile fields and avatar, email change with the password, 2FA; every success calls `updateUser` with the returned user) use the generated v1 hooks. Settings keeps its own layout (header and tabs, no side columns); chat and profile are full width outside `(main)`. The feed (`explore/components/`, on `@cm/ui`: `AddPost` is `PostComposer` validated with the contract schema and `parseServerErrors`, `FeedPost` is `PostCard` with an options menu whose Delete asks in a `Dialog`) is an infinite query whose cache is updated in place (`feedCache.ts`): a created post is prepended from the server response, a deleted one is removed optimistically and restored on error; keep mutation state that must survive such a removal in the list, not in the item component. The shell is in `src/components/shell/`: `AppHeader` (`Header` from `@cm/ui`: search to `/search?q=` when the query passes `SearchQuerySchema`, the Messages link with an unread `Badge` dot and a matching label, `UserMenu` with My profile and Log out; it reads the current user from `useAuth().user`, no request), `AppNavTabs` (`NavTabs`, current by pathname), `MainSidebar` (My communities and Events cards) and `DiscoverSidebar`; chat, profile and settings render `AppHeader` themselves. There is no notifications button until notifications exist. `Providers` clears the TanStack Query cache whenever the session becomes unauthenticated (also on logout in another tab), so cached data never leaks to the next user. After a profile change, call `updateUser` from `@cm/auth` so the header stays current. `(main)/layout.tsx` is `AppShell` with those parts. `.env.local` (see `.env.example`) holds `API_ORIGIN`, `API_URL`, `APP_ENV`, `REALTIME_URL`.

i18n (next-intl, no locale in the URL): locales `en` and `cs` (`src/i18n/config.ts`); `src/i18n/request.ts` takes the `NEXT_LOCALE` cookie, then `Accept-Language`, then `en`, and loads `messages/<locale>.json` typed by `en.json`, so a key missing in `cs.json` fails typecheck. `LanguageSwitcher` (Settings and the welcome page only) calls the `setLocale` server action, which sets the cookie; Next re-renders the page. Server components use `getTranslations`, client components `useTranslations`. Errors go through `useErrorText(scope?)` (`src/i18n/useErrorText.ts`): form field errors by `validation.<scope>.<field>.<zod issue code>` then `validation.<field>.<code>`, form and request errors by `errors.<API code>`; without a key the English text from the contract or the API is shown. Counts use ICU plurals in the messages (Czech needs one/few/other) and `useCompactNumber` for the number itself. Values that the API stores (community theme, privacy) stay English; only their labels are translated. ESLint `react/jsx-no-literals` (apps/web/eslint.config.mjs) rejects text in JSX, including template literals; only the brand name is allowed. Dates: time zone `Europe/Prague` and named formats (`date`, `time`, `dateTime`) in `src/i18n/formats.ts`; format with `useDateText()` (`date`, `time`, `dateTime`, `relative` — relative under a week, then the date — and `dayKey`/`dayLabel` for the chat's day separators: Today, Yesterday, then the date), never `toLocale…` or `Intl` directly; render dates in `<time dateTime>`.

Runtime config: `app/env.js/route.ts` serves `window.__ENV__` (the public schema of `@cm/env`, read from `process.env` per request) and the root layout loads it with `<Script strategy="beforeInteractive">`; read values with `publicEnv()` from `@cm/env`, never `process.env` or `NEXT_PUBLIC_*` in browser code. `src/proxy.ts` (Next 16 proxy, formerly middleware) rewrites `/api/v1/*` and `/uploads/*` to `API_ORIGIN` (`serverEnv()`), read per request: `rewrites()` in `next.config.ts` are fixed into the build, so one build could not serve another API origin. The API serves only `/api/v1` (the pre-v1 `/api/*` routes were removed at the end of phase 5).


## Web: rules for new code
- Server Components by default; "use client" only for state/effects/browser APIs.
- Never hardcode the API base URL in new code; do not copy the existing hardcoded usages.
- User-facing text comes from `messages/en.json` and `messages/cs.json` (both, same keys); show
  errors with `useErrorText`, never `error.message` directly.
- Forms use `useZodForm` with the request schema from @cm/contracts and report failures with
  `applyServerErrors`; show `errors.<field>` and `errors.root?.server`.
- API calls use the generated hooks of @cm/api-client (v1 endpoints); request and
  response types come from @cm/contracts / @cm/api-client, never redeclared locally.
- Styling: screens are assembled from `@cm/ui` only. No `@mui/*` / `@emotion/*` imports and no `sx` or `style` attributes in `apps/web` (ESLint `no-restricted-imports` / `no-restricted-syntax`; screens not yet migrated are listed in `notYetOnUi` in `apps/web/eslint.config.mjs` and leave it as they move). If a screen needs something the kit lacks, add a prop or a component to `@cm/ui` with a story; never a hard-coded colour, size or font. Cascade layers: `globals.css` declares `@layer legacy, mui;`; MUI's styles are in `mui` (`AppRouterCacheProvider` with `enableCssLayer` in the root layout), and the old CSS (`src/styles/*.css` and the global element rules, e.g. `button { all: unset }`) is wrapped in `@layer legacy`, so MUI components win over it while unmigrated screens keep their look; a screen's CSS file is deleted when the screen moves (phase 10c). The unlayered `body` rules in `globals.css` keep the old white page and 16px text until the last screen moves. Tests find fields by label and controls by role, not by placeholder. Poppins comes from `next/font` (`--font-poppins`).
- Existing pre-migration code is not a style reference. When unsure, ask.

## Planned direction is NOT current state
Do not implement anything from "Planned direction" unless the current step of
docs/MIGRATION_PLAN.md says so. Read that file before any migration work.

## Workflow
- Anything beyond a one-file change: plan first. Offer 2-3 options with
  trade-offs (complexity, blast radius, risk) and recommend one.
- Changing a contract in @cm/contracts: list every consumer in api and web before editing.
- Done means: `pnpm turbo run typecheck lint circular --filter="...[HEAD]"` passes.
  Report the actual output, do not assume it passes.

## Documentation (Context7 MCP)
- Before writing code that uses Next.js, React, Express, Sequelize, NextA//uth,
  TanStack Query, Socket.IO or zod APIs, fetch current docs via Context7.
- Take versions from package.json and request docs for those versions.
- Mandatory for: Next caching, routing, server actions, next.config, Express 5
  routing/error handling.
- Do not call Context7 for plain TypeScript logic with no third-party API.

## Conventions

- Comments only explain a non-obvious *why*; no JSDoc or descriptive comments restating the code.
- API code style: 4-space indent, single quotes, snake_case DB columns/model attributes (`user_id`, `created_at`), camelCase in contracts where already established.
- Migration work proceeds one plan step at a time; after verifying (typecheck/lint/build/circular/knip/syncpack + live smoke test), stop and propose a commit message — the user commits themselves.
