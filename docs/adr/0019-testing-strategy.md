# 0019. Testing strategy

Status: Accepted

## Context

The project had no automated tests before the migration.

## Decision

Four levels, all with Vitest except end-to-end:
- Unit tests in the packages and `apps/api/test/unit` (no database).
- API integration tests against a throwaway MySQL database, asserting responses with the contract schemas.
- Web component tests (jsdom, Testing Library) with MSW handlers generated by orval, fixed fixtures, the real `@cm/auth` session and the React Compiler applied.
- Playwright end-to-end tests (`e2e/`) against built apps on their own ports and a throwaway database, with users created through the API.

## Consequences

- Unhandled network requests fail web tests.
- End-to-end tests do not touch a running `pnpm dev`.
- Pre-commit runs unit and component tests; CI also runs integration and end-to-end tests.
