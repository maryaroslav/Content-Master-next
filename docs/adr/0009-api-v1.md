# 0009. Versioned API under /api/v1, migrated route by route (D10)

Status: Accepted, completed

## Context

Switching every screen to new endpoints at once would have been a big-bang change with no way back.

## Decision

New endpoints were added under `/api/v1` next to the old `/api/*` routes, and screens were moved one by one (strangler pattern). When the last screen had moved (end of phase 5), the old routes and their legacy contracts were removed.

## Consequences

- The API serves only `/api/v1`.
- Breaking changes from now on would go to a new prefix.
