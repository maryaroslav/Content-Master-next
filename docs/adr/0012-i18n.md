# 0012. next-intl with English and Czech, no locale in the URL (D12)

Status: Accepted (supersedes the en/ru plan)

## Context

The UI text was hardcoded in English. The original plan named `en` and `ru`; the app targets Czech users, so the second locale became `cs`.

## Decision

next-intl without locale prefixes: the `NEXT_LOCALE` cookie, then `Accept-Language`, then `en`. Messages live in `apps/web/messages/{en,cs}.json`, typed by `en.json`, so a key missing in `cs.json` fails typecheck. Errors are translated by API code (`useErrorText`), dates are formatted in `Europe/Prague` (`useDateText`), and ESLint `react/jsx-no-literals` rejects text in JSX.

## Consequences

- URLs stay the same in both languages.
- Values stored by the API (theme, privacy) stay English; only their labels are translated.
- A second app would keep its own messages instead of sharing a package.
